# KF-AUDIT-037 — next implementation cluster, not a completed fix

Current evidence: preview/app-state.js reads the shared credential from localStorage/sessionStorage and many frontend modules attach it directly. KappaWebView.credentialScript injects the Keychain credential into page sessionStorage; the credentials bridge migrates storage but does not remove script access to the long-lived key. CredentialVault itself already uses WhenUnlockedThisDeviceOnly. Preserve that native storage and existing operation-authorization checks.

Removing a localStorage write alone cannot close037: the credential is still in page globals, bootstrap scripts and the current connection form. A new root token must never be introduced to the page as a replacement.

## Proposed contract and migration

1. Retain the existing Worker as gateway and its Durable Object capacity. Add a device-session namespace/service using hashed opaque credentials, server-clock expiry, explicit device identity, fixed scopes and serialized issue/revoke/renew decisions. No new recurring service is required.
2. Root bootstrap/admin credentials may enroll/revoke devices only through an independently authenticated owner channel. Normal device tokens cannot enroll devices, broaden scopes or approve protected financial/security/deployment operations. Keep existing no-merge/deploy and signed task-authority boundaries.
3. Use short access sessions (proposed maximum5 minutes) in page memory. Store the native renewal credential only in Keychain; it can renew its own bounded scopes, not call ordinary/admin APIs directly. Check current device revocation on every authenticated request; a self-contained expiring token alone does not meet immediate revocation. Rate-limit renewal independently from model quotas.
4. Enroll through a native secure connection view/URLSession operation, not an HTML root-password form. Restrict credential-bearing native requests to the exact configured HTTPS origin and allowed session paths. Reject cross-origin redirects, arbitrary headers, administrative paths and uncorrelated callbacks. JSON-encode callbacks; never interpolate untrusted source into executable JavaScript.
5. Replace native root injection with a nonsecret connection-state bootstrap and a narrow session-renewal bridge. A bootstrap or renewal failure must remain a visible disconnected state, not fall back to injecting the root. Preserve chats, encrypted vault and owner recovery material; do not erase unrelated storage.
6. Centralize frontend authenticated requests rather than patching dozens of headers independently. Preserve cancellation, NDJSON token streaming, uploads, voice and timeout handling. Remove long-lived credentials from globals, both storage APIs, diagnostic/export paths and user scripts. An access session remains usable by a compromised active page within its narrow lifetime; this is not a claim that XSS becomes harmless.
7. The published interface is currently native-only. A future browser deployment needs same-origin secure HttpOnly renewal or a reviewed passkey flow. Do not pretend third-party cookies from file:// or the retired Pages site provide a secure persistent browser session. Mark unsupported enrollment explicitly until implemented.
8. Stage server compatibility and client migration on isolated candidates. An owner-controlled rollout flag may temporarily admit old clients; it is not a fix while legacy shared-bearer access remains enabled. End the migration only after upgraded devices work and an explicit approved server rollout disables legacy admission. No production flag/token/permission change is authorized by this document.

## Concrete acceptance

- Real session store: issue, expire, renew, concurrent renewal, revoke and worker restart fixtures. Revoked access/renewal credentials fail immediately and cannot resurrect through race/replay. Missing store fails closed; no request is silently promoted to root authority.
- API matrix: device tokens work only on declared routes/scopes; root/admin and signed owner approvals remain distinct. Negative cases cover malformed/forged/expired tokens, copied device ids, wrong origin, redirects and denied costly/consequential actions. No credential values in logs or receipts.
- Browser injection fixture: inspect localStorage/sessionStorage, globals and native bootstrap script and find no root/long-lived renewal credential. Stealing a short access token must not enroll another device or acquire administrative authority. This does not assert that arbitrary actions are safe under XSS.
- Native simulator: secure enrollment, app/background restart, locked-Keychain denial, renewal/cancellation, streaming chat and migration cleanup pass while all existing five UI tests remain. Real device coverage is explicitly separate.
- Compatibility: independent old/new client/server matrix, visible renewal failure, recoverable owner enrollment and safe rollback without losing vault/chats. Disabling legacy production auth requires a concrete owner-approved rollout, after these tests.

Potential components: chat-backend/src/session-store.js and session-auth.js; existing KappaMemory routing/index auth; preview authenticated transport and connection settings; native CredentialVault, secure connection UI and restricted bridge; Worker/browser/native integration fixtures. These names are proposed components, not claims of files already implemented.

Owner decisions before eventual rollout: desired device/session lifetime, browser scope, recovery/enrollment channel, and whether revoking a device also cancels already owner-authorized tasks. Default design should revoke future device access while retaining separately authorized task progress until cancellation/expiry; make that behavior explicit. Routine isolated implementation/tests do not require another permission request.
