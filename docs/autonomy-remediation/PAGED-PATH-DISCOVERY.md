# Large-repository path discovery — KF-AUDIT-014 partial

The initial planner listing builds from at most700 sorted paths and then ranks/deduplicates down to60 prompt entries. Previously, a planner with no relevant visible path had to guess a file or fail before investigation. Full repository search also risked loading unrelated file contents merely to identify a filename.

The existing exploration loop now exposes `find_paths(query="", path_prefix="", page=1)`. It searches the complete admitted immutable revision inventory, returns20 bounded metadata entries per page and explicit total/pages/repository count, and reads no file content. Queries are literal case-insensitive substrings; path prefixes and page types are validated. Files remain confined to the existing authorized repository snapshot. Finding a filename is explicitly not evidence of source behavior or task completion. Output/call/time limits use the existing durable exploration ledger; no limits or model budgets are raised.

The planner reports exact displayed/omitted path counts and may return an empty initial read list with a specific investigation question. A valid inquiry is not a malformed planning response or reason to read unrelated fallback paths. Develop's existing investigation then obtains current source through tools and adds only actually read files to generation/plan evidence. Repair receives the same tool automatically through the existing whitelist/controller adapter; no second execution loop is added.

Executed deterministic acceptance discovers a target beyond index700, reads it from the observed path result, derives the unplanned dependency from its actual import AST, and reads that dependency. Only those two files are downloaded; the full inventory never enters prompt context. The model transport is scripted and offline: this establishes tool/protocol behavior, not live model reasoning or general autonomy. Negative tests cover unsafe paths, invalid arguments, metadata-only listing, pagination and exhaustion across restart.

Remaining scope: stage/subgoal expansion beyond the existing five-stage planning window, complete durable observation retrieval/unified generation/runtime protocol, live-model task outcomes and actual deployed revision remain separate/open. No claims that every large repository is now exhaustively investigated or that the entire gap is closed.
