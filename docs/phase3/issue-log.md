## P3-010 — large review files starve later scope evidence

- Evidence: run [40230735448](https://github.com/onlykappa/KappaForge/actions/runs/40230735448) left the review incomplete with `ScopeReviewUnavailable: File scope evidence does not match current source`. Both reviewer responses failed to supply usable evidence. The bounded source builder fills its budget sequentially, while the scope prompt requires evidence for every PR file. Under gateway shrinking, an earlier large file can consume all source space and omit later files entirely.
- Reproducer: bounded multi-file scope review with a large earlier source and smaller gateway prompt budget; assert every file requiring a scope decision has current source in the actual reviewer prompt.
- Reproduction before patch: `py -3 -X utf8 -m unittest tests.test_task_goal.TaskGoalTests.test_scope_review_keeps_current_evidence_for_every_file_when_gateway_shrinks_context` — 1 test, FAILED: the later file's current evidence was absent from the model prompt.
- Permanent patch: scope reviews reserve a share of the shrinking context budget for every directly reviewed file, including test and generated files, before dependencies. Other review flows retain their existing requested-file expansion behavior. Partial sources remain explicitly labeled; missing evidence never authorizes source repair. Literal quote validation and unrelated-change rejection are unchanged.
- Immediate rerun: the reproducer passed (1 test). Related task-goal, review, and repair regressions passed (77 invocations, including the reproducer twice).
- Broader validation: full Python suite OK, 1,008 tests run, 33 skipped, both online (57.462 seconds) and with all four HTTP(S) proxy variables pointed at `127.0.0.1:9` (60.892 seconds); `npm test` passed 858/858; baseline Node checks passed 273/273; dependency map generation/check, execution-policy check and `git diff --check` passed. Web syntax/configuration/bundle check passed using installed Python with `PYTHONUTF8=1` and translating its child `python3` invocation to that same interpreter: the unadapted Windows command initially failed because `python3` is a Store alias, and the first child rerun lacked UTF-8 mode. No repository check was removed or weakened. Native/Docker checks have not run locally for this patch; the prior head's GitHub test/native success is inspected evidence only. Live candidate retry pending.
- Status: PATCHED — deterministic reproducer passes; live review result pending. The source omission is reproduced; the exact reason each live model invented its quotes is not observable.

Every pass keeps the existing evidence validation, and the owner, candidate and source snapshot are rechecked before/after every batch. A failed or stale batch raises instead of returning partial repair authorization. The existing test that rejects 13 findings sent directly to a single pass is unchanged.
- Immediate rerun: 103 repair-guard, root-cause, task-goal and review tests passed, including 39 findings across four batches, duplicate input de-duplication, late candidate movement, late verifier failure, and total-budget exhaustion.
- Broader checks actually run: Python online — 1,013 run, OK, 33 skipped, 57.212 seconds; proxy-blocked repeat — 1,013 run, OK, 33 skipped, 61.569 seconds. npm — 858 passed; baseline Node — 273 passed. Details and pre-merge interruption limits: [engine-recovery.md](engine-recovery.md).
- Regression: the engine-selection test was run against the previous Journal implementation and FAILED because the dispatch ref was `main`. The same regression passes after the patch. Focused runtime/recovery/admission tests: 94 passed, covering forged and malformed receipts, current-main promotion, stale checkouts, reservation movement, cancellation, unavailable provenance and no parallel scanner dispatch.
