## Phase 4 implementation in this branch

- Owner-authored `Mode: develop` tasks may optionally include one exact `Inference route: groq:openai/gpt-oss-120b` line. The accepted route is deliberately narrow and must still intersect the configured task code-provider allowlist and the server-side free-model policy.

It verifies the gateway returned that same route. Unsupported/duplicate pins or a pin outside the current coding allowlist fail closed. Tasks without a pin retain the existing general routing policy.
- The task-body digest binds the route choice to its authorization; continuations re-read the same open issue and therefore keep the same route restriction. Durable waiting/failure events now retain the pinned provider/model, so app progress can show which route was unavailable. Provider cooldown waits do not consume continuation attempts.
- No user-facing app source or existing dashboard configuration is changed.
- Gateway failures now retain allowlisted error codes, HTTP status, Retry-After/reset metadata, and available structured failure details. They propagate through generation and review rather than triggering compact/replanning calls. Pinned tasks never queue automatic continuation after failure.
- Bounded pinned inference uses at most four requests, a 768-token output ceiling, 26,000-character prompt ceiling, and a persisted minimum 65-second interval. These are local conservative request bounds, not changes to provider or gateway quota settings and not guarantees about tokenizer/account allowance.
- An optional owner-bound `Edit path: docs/integration/<name>.md` restricts the acceptance task to exactly one new nonempty Markdown file. Deterministic planning uses the named style reference; generation preserves the exact task and full repository guidance. No prompt compression or instruction truncation is introduced.

- Empty final deltas reuse the existing checkpoint commit rather than submitting an empty Git tree and making duplicate commits.
