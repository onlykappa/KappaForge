# KappaForge 2.0 architecture and recovery

Audit baseline: 2ea5ea58b90408e93a7f70ccdd50a161b62320ca.

`preview/` is canonical. `scripts/bundle-web.py` copies the same eight files into the existing `ios/KappaForge/Web` resource folder. It verifies the interface version, web manifest version and native marketing version. The app retains `com.onlykappa.KappaForge`, its persistent default WKWebsiteDataStore and file URL. No redirect to GitHub Pages is used. Native settings contain only device security and native version/update details; application settings use the shared interface.

The Cloudflare Worker retains its bearer-token and exact-origin checks. New POST `/capabilities` discovers allowed Gemini models and reports configured services, not user-account verification. POST `/usage` returns 500 events per page with an opaque validated cursor, stored in the existing owner-v1 Durable Object using separate `usage:` keys. Events contain no prompts, replies, credentials or memory. Retention is 90 days with incremental cleanup on new records. UTC aggregation does not assume shared browser/iOS storage. Every provider attempt records available usageMetadata, including totalTokenCount which may include thinking tokens. Failed attempts have unknown costs/tokens, never invented zeros. Provider discovery failures occur before an AI generation attempt and appear in diagnostics rather than the usage ledger.

`MONTHLY_REQUEST_LIMIT` is an optional positive integer Worker variable. It atomically reserves accepted generation calls per UTC month before execution. Every reserved call can make up to two provider attempts. Failures consume the reservation. It is not a currency spending cap. UI budgets are advisory thresholds over loaded data. Output limits are capped at 500/1200/3000 tokens by response detail. Provider generation timeouts are 45 seconds per attempt. Automatic cost preference uses approved Lite models and does not claim live price optimization.

`MODEL_PRICING_JSON` is optional, and costs remain null without it. Example schema (substitute independently verified rates, never copy test prices): `{ "model-name": { "input": <USD per million input tokens>, "output": <USD per million output tokens>, "source": "https://provider-pricing-source", "asOf": "YYYY-MM-DD" } }`. Provider thinking/cache/tool pricing may differ; estimates use reported input/output only. Errors cannot establish billable cost. Historical estimates are stored with the event; no retrospective inferred prices.

Existing local keys and encrypted vault envelope v1 are preserved. The encrypted payload gains optional preferences, preference timestamp, note categories and per-note deletion/restoration timestamps. Older backups remain readable. No new encryption key is generated for an existing device wrapping key. Automatic sync merges chats by existing ID/timestamp, notes by text plus tombstones, preferences by timestamp. No credentials are synced. Physical devices require the same backend token and the same original vault passphrase entered separately. Export an encrypted backup and verify import before changing devices. Existing 280 KB encrypted payload bound and 60-chat cloud snapshot bound remain; older local chats are never replaced during automatic merge. File export/import merges data. Automatic sync stops on decryption/conflict/storage errors rather than wiping the vault. Category changes on different devices can conflict; device clocks affect merge ordering.

Native access tokens migrate to a Keychain generic-password item with WhenUnlockedThisDeviceOnly accessibility. Browser persistent credentials are removed only after Keychain write success; failure preserves the old configuration. Browser Safari credentials remain unchanged. Biometric locking is opt-in and evaluated before enabling; lock applies at launch/background with device-passcode recovery. It is an interface lock, not encryption of existing browser data. Backups shared through native UI are already encrypted before temporary file creation. Usage export is user-requested plaintext metadata.

Release sequence: reusable shared web regression -> GitHub Pages deployment -> reusable macOS simulator build/launch -> iPhone unsigned package verification -> immutable versioned GitHub release. Backend deploy validates Worker syntax, integration tests and Wrangler bundling independently with existing Cloudflare secrets. Web releases do not wait for iOS. No physical-device authentication or sideloading is required for a web deploy. A manual iOS workflow validates a selected branch and never publishes. Bump interface/native/version.json together for later releases; installed versions do not change until SideStore installs a signed IPA.

POST `/memory/search` runs opt-in transient Workers AI note embeddings, with limits of 100 notes and 300 query characters, and does not persist plaintext notes or vectors. Text/category search remains entirely local. POST `/projects/health` restricts GitHub inspection to the existing three repositories, reports workflow failures and failed job steps, root manifests and Dependabot alerts. Missing scopes are surfaced as unavailable; diagnostics never change repository or security configuration.
